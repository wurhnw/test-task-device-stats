# Нагрузочное тестирование (Locust)

## Сценарий

`locustfile.py` имитирует работу с устройством:

| Доля | Запрос                          | Что делает                            |
|------|---------------------------------|----------------------------------------|
| 5    | `POST /devices/:id/readings`    | Отправляет измерение `{x, y, z}`       |
| 2    | `GET /devices/:id/stats`        | Запрашивает статистику по устройству   |
| 1    | `GET /users/:id/stats`          | Запрашивает статистику по пользователю |

Каждый виртуальный пользователь в `on_start` создаёт собственного `User` и
`Device`, после чего непрерывно отправляет запросы с паузой 100–500 ms.

## Запуск через Docker Compose

```bash
docker compose up -d           # поднять API, БД, Redis и воркер
docker compose --profile loadtest up locust
# UI: http://localhost:8089
```

## Запуск headless

```bash
locust -f locustfile.py --host http://localhost:8000 \
       --headless -u 50 -r 10 -t 30s --csv loadtest/report
```

## Параметры прогона

| Параметр                 | Значение            |
|--------------------------|---------------------|
| Виртуальных пользователей| 50                  |
| Ramp-up                  | 10 пользователей/с  |
| Длительность             | 30 секунд           |
| Стенд                    | API на одном Uvicorn-процессе, БД, локально |

## Замечания

- Тест проводился на SQLite (в sandbox-окружении без Docker), что увеличивает
  накладные расходы на запись. На PostgreSQL (рекомендуемая конфигурация)
  пропускная способность ожидаемо выше за счёт пула соединений и эффективного
  индекса по `(device_id, created_at)`.
- При необходимости стресс-теста можно поднять `-u` до 200–500 и подключить
  несколько воркеров через `--master` / `--worker`.
